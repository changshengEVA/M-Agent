# M-Agent 愿景与项目目标

> 文档状态：当前权威定位  
> 确认日期：2026-08-04  
> 适用范围：M-Agent v0.2.0 及后续版本

## 1. 项目愿景

> **让 Agent 的认知不再以用户消息为边界，而由世界变化、行动结果、时间条件和内部预期持续驱动。**

现实中的变化是异步、异构并且带有噪声的。用户消息只是其中一种来源；邮件、日程、网页变化、工具结果、截止时间以及“预期事件没有发生”都可能要求 Agent 重新判断当前状态。

M-Agent 研究并实现的核心问题是：

> **Agent 如何在开放刺激流中，只在正确的时刻，因为正确的原因，形成正确的认知上下文并更新正确的持续事务。**

## 2. 技术定位

M-Agent 是一个 **Stimulus-Native Cognitive Runtime（刺激原生认知运行时）**。

它不把一次 LLM 调用视为 Agent 的完整生命周期，而是在模型调用之外持续维护刺激、事务、目标、状态、记忆、预期、权限和行动结果。Runtime 在需要认知时构造本次上下文，在无需认知时保持状态而不持续消耗模型资源。

核心技术主线称为 **Stimulus-to-Cognition Compilation（刺激到认知的编译）**：

```text
Signal
→ Observation
→ Stimulus
→ Admission / Attention
→ Goal / Transaction Attribution
→ Cognitive State Transition
→ Context Snapshot c
→ Action / Silence
→ Effect Feedback
```

其中：

- `Signal` 是外界或系统发生的原始变化；
- `Observation` 是带有来源、时间和可信度的观察；
- `Stimulus` 是被判断为可能与当前 Agent 有关的认知输入；
- `Context Snapshot c` 是某次激活中供模型决策的最小充分认知快照；
- Runtime 是长期维护状态并反复构造 `c` 的执行环境，`c` 本身不是 Runtime。

## 3. 产品目标

技术定位面向开发者，最终用户价值表达为：

> **说一次，持续接得上；需要你时才出现。**

个人助手应当做到：

- 用户无需在每次交互中重新说明正在处理什么；
- 用户无需为每项事务手工编写自动化工作流；
- 来自不同信息源的变化能够自动接回正确事务；
- 无关、重复、过期和低价值刺激尽量被静默处理；
- 只有需要用户判断、补充信息或授权时才主动出现；
- 每次唤醒、状态变化与外部行动都可以解释和追溯。

## 4. 面向开发者的承诺

M-Agent 不以连接器数量作为核心竞争力。开发者接入一个观察源后，Runtime 应当提供可复用的公共能力：

1. 对信号进行来源校验、去重、时序处理与持久接纳；
2. 由内核给出确定性池状态与处置（拒绝/合并/丢弃/完成/中止/失败）；“该不该理 / ignored”留给 Attention；
3. 在缺少显式 `transaction_id` 时，将刺激归因到正确目标或事务；
4. 以证据化状态迁移更新持续认知状态；
5. 编译可检查、可回放的 `Context Snapshot`；
6. 对行动应用确定性的权限、预算和审批策略；
7. 将 Effect 结果作为新刺激重新进入同一因果闭环；
8. 在崩溃、重启、重复投递和并发条件下保持明确处置。

## 5. 系统记忆与工具记忆

M-Agent 明确区分两种记忆使用方式。

### 5.1 工具记忆

工具记忆由模型主动调用，例如搜索、RAG 或档案查询。它适合扩展探索，但不能保证模型总能意识到自己需要回忆。

### 5.2 系统记忆

系统记忆由 Runtime 自动维护。已提交的 Scene、TaskState、Evidence 和 Effect 经投影、整合与检索后，由 Context Compiler 在决策前评估是否进入 `c`。每条记忆必须保留来源、时间、置信度、作用域和生命周期。

两者的区别不在数据库，而在控制权：

- **工具记忆：模型想起后主动查询。**
- **系统记忆：Runtime 保证必要记忆在决策前得到评估。**

## 6. Strategy 的定位

Strategy 是程序性知识，回答“在某类情境中通常应如何组织目标、步骤与决策”。它不等同于历史事实、用户偏好、工具结果、系统规则或模型思维链。

Strategy 必须作为独立系统接入，并遵守以下边界：

- 不能创造事实或替代 Observed Evidence；
- 不能自行把任务标记为完成；
- 不能绕过能力权限、审批策略和资源预算；
- 必须保留来源、适用条件、版本和使用 Trace；
- 必须按照 `Shadow → Opt-in → 评测达标 → 默认候选` 的顺序上线。

## 7. v1.0 之前的非目标

以下内容不属于 v1.0 的稳定承诺：

- 人类级意识、情绪体验或“数字生命”声明；
- 通过持续调用 LLM 模拟持续思考；
- 无限制自主目标生成、模型自修改或在线自强化；
- 多节点高可用与任意第三方副作用的绝对 Exactly Once；
- 原始音视频连续流或机器人实时控制；
- 把某种 Prompt、模型供应商或内部 LangGraph 拓扑冻结为公共契约。

## 8. 成功判据

M-Agent 的目标是否成立，应由以下可执行结果判断，而不是由模型自述判断：

- 刺激处置准确率与误唤醒率；
- 无显式事务 ID 时的事务归因准确率；
- 状态迁移与 Context 证据正确性；
- 不必要打扰率和关键刺激漏检率；
- 跨重启恢复、重复投递与副作用语义；
- 系统记忆、Strategy 的消融收益和失败案例；
- 用户是否能够“只表达一次”，仍让后续变化正确接回原事务。
